Phase 7 PV充電補正係数 実装計画

目的

天気予報の日射量から算出したPV発電予測を、そのまま深夜充電計画へ使わない。毎日の予測値と実際にEcoFlowへ充電できた量を比較し、PV発電予測に掛ける補正係数を提案できるようにする。

あわせて、DELTA Pro 3 だけでなく DELTA 3 Plus も機器ごとの日中負荷を持つ前提にし、全機器の必要量、利用可能量、PV割当、深夜充電目標SOCを計算できるようにする。

最初は補正係数の手動適用を基本とし、十分なログが取れてから自動適用できる余地を残す。初期実装では自動適用トグルは出さず、明示操作で保存された補正係数だけを制御計算に使う。

背景

現在の深夜充電プランは、Open-Meteoの日射量から推定PV発電量を計算し、EcoFlowの過去出力ログから日中使用量を差し引いて、翌日の深夜充電目標を決めている。

ただし、予測PV発電量の全量がEcoFlow充電へ回るとは限らない。

  • 家全体の消費に先に使われる。
  • EcoFlowのAC入力上限、最低充電W、満充電、バックアップリザーブに制約される。
  • DELTA Pro 3とDELTA 3 Plusの受け入れ可能量が時間帯で変わる。
  • 売電していても、制御条件により充電へ取り込めない時間がある。
  • 天気予報の日射量と実際の発電量にはズレがある。
  • DELTA 3 Plus が日中に約400W程度を担当する前提が、深夜充電プランの不足量に十分反映されていない。
補正後PV充電見込みkWh = 予測PV発電kWh * PV充電補正係数

補正後PV充電見込みは「全機器向けのPV充電余力」として扱い、優先順位順に各機器へ配分する。

非目的

  • EcoFlowの安全ゲートを緩めない。
  • 実機writeを無条件に増やさない。
  • Nature RemoやEcoFlowの認証情報を保存しない。
  • 自動適用を初期状態で有効化しない。
  • 機器別の充電制御を根本的に作り直さない。
  • 機器マスターを使わずに .env の固定台数で制御しない。

settings には pv_charge_correction_factor に加えて、pv_charge_correction_manual と pv_charge_correction_updated_at を保存する。移行直後の0.7は既定値として pvChargeCorrectionSource=default を返し、UIで明示保存された場合だけ manual として扱う。

night_charge_plan_logs

補正係数は requiredNightChargeKwh の算出結果を変えるため、夜間制御判断ログにも、判断時点の補正係数、補正元、補正後PV発電見込み、補正後PV充電見込み、全機器の日中必要量、利用可能量、不足量を保存する。これにより、後からなぜその深夜充電目標になったかを再現できるようにする。

充電機器マスター

既存の機器マスターを深夜計画の入力として使う。既存カラムの priority、capacity_wh、backup_reserve_min_soc、backup_reserve_max_soc、max_charge_w、control_enabled を使い、機器別の必要量と目標SOCを計算する。

expected_daytime_load_w は新規に charging_devices へ追加する。既存DBでは既定0Wのまま追加し、DELTA 3 Plus の400W想定はマスター編集画面から設定する。自動で全機器へ400Wを入れない。

日次評価ログ

新規テーブル pv_charge_correction_daily_logs を追加し、予測PV、PV有効時間帯の実充電量、売電実績、算出係数、品質を保存する。評価対象日の date は UNIQUE とし、再生成時は upsert で同じ日を上書きする。これにより okSampleDays や平均係数が同じ日で重複しないようにする。

power_logs.battery_input_w は主機側の入力であり、DELTA 3 Plus のAC入力は現在の機器ステータスには出ているが永続化されていない。そのため、全機器のPV捕捉量を評価するために charging_device_power_logs を追加し、機器別のSOC、AC入力、AC出力、AC充電上限、バックアップリザーブ、取得可否を保存する。

actual_battery_input_kwh は、原則として機器別の実質充電量を使う。DELTA 3 Plus のようにAC入力とAC出力が同時に出る機器では、charging_device_power_logs.ac_input_w をそのまま加算しない。基本式は max(0, ac_input_w - abs(ac_output_w)) とし、SOC増分からより確実に蓄電量を推定できる場合はSOC増分を優先する。ac_input_w と abs(ac_output_w) が近いパススルー状態は、バッテリー充電実績ではなく負荷供給として扱い、PV捕捉量から除外する。

移行直後など補助機器履歴が不足する日、またはパススルーが多く実質充電量を判定できない日は sample_quality=insufficient-data にし、主機だけの値や生のAC入力値で全機器向け係数を出さない。

実充電量の集計では、深夜充電や買電によるAC充電をPV捕捉量に混ぜない。対象はPV有効時間帯に限定し、export_w > 0、または import_w == 0 かつ制御コマンド影響外のサンプルだけを採用する。夜間充電、買電中の充電、直近に充電制御コマンドが実行された区間は不足または除外として扱う。

補正係数の算出

  1. 直近N日から sample_quality=ok の日を抽出する。
  2. PV有効時間帯かつ非買電/売電寄りのサンプルから actual_capture_factor を計算する。
  3. 夜間充電、買電充電、制御コマンド直後の区間を除外する。
  4. 0未満、1超過、予測PVが極端に少ない日を除外する。
  5. sample_quality=ok の日数が pv_charge_correction_min_sample_days 未満なら、推奨値は insufficient-samples として適用不可にする。
  6. 閾値を満たした場合だけ、初期実装では直近OK日の平均を推奨値にする。
  7. 下限から上限の範囲に丸める。

機器別日中負荷とPV配分

DELTA Pro 3 は既存どおり power_logs.battery_output_w の履歴から日中必要量を推定する。DELTA 3 Plus は初期実装では機器マスターの expected_daytime_load_w とPV有効時間から推定する。例として 400W が7時間続く場合は 2.8kWh とする。

利用可能kWh = (capacity_wh / 1000) * max(0, (current_soc - backup_reserve_min_soc) / 100)

backup_reserve_min_soc は機器本体の最低放電残量ではなく、このシステムが放電方向に制御してよい下限として扱う。backup_reserve_max_soc は深夜充電で引き上げてもよい上限として扱う。

補正後PV充電見込みは全機器用の充電余力として扱う。推定余剰が 1.2kWh の場合も、DELTA Pro 3 だけでなく全機器で共有する値として扱い、優先順位順に不足機器へ割り当てる。

ただし、既存の morningToPvStartLoadKwh はPV有効時間が始まる前に必要な電力量として、PV割当前に深夜充電必要量へ確保する。朝7時以降からPV開始までの負荷は、日中のPVでは後から補えないため、補正後PV充電見込みから差し引かない。

さらに、既存plannerが確保している estimatedMorningLoadKwh と safetyMarginKwh も、深夜中から7時までの残り負荷と安全マージンとしてPV割当前に必ず確保する。

深夜残り確保kWh = estimatedMorningLoadKwh + safetyMarginKwh
朝PV開始前不足kWh = max(0, morningToPvStartLoadKwh - 現在利用可能量kWh)
PVで相殺可能な不足kWh = max(0, 日中不足kWh - 朝PV開始前不足kWh)
深夜で必ず確保するkWh = 深夜残り確保kWh + 朝PV開始前不足kWh

最終的には、深夜残り確保、朝PV開始前不足、PV割当後も残る不足を深夜充電必要量にし、機器ごとの目標SOCへ変換する。

深夜充電プランへの反映

nightChargePlan に補正係数、補正後PV見込み、補正元、推奨値、全体の日中必要量、利用可能量、不足量を追加する。推奨値には recommendedFactor、okSampleDays、minSampleDays、applicable、status を含める。JSON名は既存の Kwh 表記に合わせ、全体値は totalDaytimeRequiredKwh、totalAvailableKwh、totalDeficitKwh とする。補正後の深夜必要充電量は既存の requiredNightChargeKwh を更新し、別名フィールドは追加しない。機器別情報は既存の devicePlans を拡張し、daytimeRequiredKwh、availableKwh、pvAllocatedKwh、不足理由を持たせる。機器別の深夜必要量は既存の requiredChargeKwh を更新し、別名フィールドは追加しない。補正後の機器別目標は既存の recommendedTargetSoc / recommendedTargetKwh を更新し、targetSoc は機器マスター設定値として残す。制御判断では補正後のPV見込みを使い、補正前の予測値は表示用に残す。

API

  • GET /api/status: nightChargePlan に補正情報を追加する。
  • GET /api/pv-charge-correction: 現在設定、推奨値、日次評価ログ、機器別の日中必要量、PV割当、既存 requiredChargeKwh に反映された深夜必要量を返す。
  • POST /api/pv-charge-correction: UIから明示保存された補正値だけを更新する。係数は pv_charge_correction_min_factor から pv_charge_correction_max_factor の範囲で検証し、範囲外、NaN、無限大、数値でない入力は 400 Bad Request とする。

UI

設定ブロックに「PV充電補正」を追加し、現在値、推奨値、サンプル日数、補正前PV予測、補正後PV充電見込み、実充電量平均、推奨値適用ボタンを表示する。自動適用トグルは今回表示しない。

深夜充電プランには、全体の日中総必要量、全機器の利用可能量、全機器不足量、既存 requiredNightChargeKwh に反映された深夜必要充電量を表示する。機器別には、現在SOC、日中必要量、利用可能量、PV割当、既存 requiredChargeKwh に反映された深夜必要量、推奨目標SOC、不足理由を表示する。

安全境界

  • 実機write条件は変更しない。
  • 補正係数は深夜充電の目標計算にのみ影響する。
  • 補正係数の変更履歴をログに残す。
  • 初期値は保守的に0.7とし、予測PV全量を充電可能とは扱わない。
  • サンプル不足時は推奨値を適用不可にし、UIから適用できないようにする。
  • 自動適用は今回追加しない。
  • 機器別目標を計算したあとも、既存の制御ゲート、コマンド間隔、405/AC出力OFF抑止条件を維持する。

実装ステップ

  1. domainにPV充電補正設定、推奨値、日次ログ型を追加する。
  2. SQLiteマイグレーションで設定項目と日次ログテーブルを追加する。
  3. charging_device_power_logs を追加し、DELTA Pro 3 / DELTA 3 Plus の機器別SOC、AC入力、AC出力、AC充電上限を保存する。
  4. night_charge_plan_logs に補正係数、補正元、補正後PV見込み、全機器必要量/利用可能量/不足量を保存する。
  5. power_logs、charging_device_power_logs、既存の夜間充電プランログから日次評価ログを生成する repository/service を追加する。
  6. charging_devices に expected_daytime_load_w を追加し、domain/repository/API/UIで編集・表示できるようにする。
  7. 機器マスターから優先順位、capacity_wh、backup_reserve_min_soc、backup_reserve_max_soc、想定日中負荷Wを読み込み、機器別日中必要量を計算する。
  8. DELTA Pro 3 は既存履歴、DELTA 3 Plus は初期実装では想定日中負荷Wを使う。
  9. 深夜残り負荷、安全マージン、朝PV開始前不足をPV割当前に深夜充電必要量として確保する。
  10. 補正後PV充電見込みを全機器に優先順位順で配分し、既存の devicePlans にPV割当、既存 requiredChargeKwh で表す深夜必要量、目標SOCを追加する。
  11. 深夜充電プランに補正係数と機器別計画を入力し、制御用PV見込みを補正後に差し替える。
  12. /api/pv-charge-correction のGET/POSTを追加する。
  13. frontendの型、API、設定UI、深夜充電プラン表示を更新する。
  14. 単体テストを追加する。
  15. build/test/reviewを実施する。

レビューポイント

  • 予測PV全量を充電可能として扱っていないか。
  • サンプル不足時に誤った推奨値を出していないか。
  • 深夜充電や買電充電がPV捕捉量として混ざっていないか。
  • DELTA 3 Plus の実質充電量が補正係数の実績値から抜けていないか。
  • DELTA 3 Plus のパススルーAC入力をバッテリー充電実績として加算していないか。
  • 自動適用が初期実装に紛れ込んでいないか。
  • 実機writeゲートが緩んでいないか。
  • UIの「推奨値」と「現在設定値」が混ざって見えないか。
  • DELTA Pro 3 / DELTA 3 Plus の制御対象が機器マスター前提から逸脱していないか。
  • 推定PV余剰をDELTA Pro 3専用として扱っていないか。
  • DELTA 3 Plus の400W級日中負荷が不足量に反映されているか。
  • 深夜残り負荷、安全マージン、朝PV開始前不足がPV割当前に確保されているか。
  • 目標SOCが backup_reserve_min_soc と backup_reserve_max_soc の範囲内に丸められているか。
  • 既存の devicePlans を拡張しており、別名フィールドでUI表示が分裂していないか。
  • 夜間制御ログに補正係数、補正元、補正後PV見込みが保存され、後から再現できるか。

運用メモ

補正係数は、最初は手動で様子を見る。最低7日分のログが取れ、推奨値が安定してから自動適用を検討する。自動適用を追加する場合は、急激な変動を避けるため1日あたりの変更幅を制限し、別途レビューを通す。

DELTA 3 Plus の想定日中負荷は、初期値400Wを目安にする。ただし実際の接続機器や稼働状態で変わるため、機器マスターで変更できるようにし、将来は機器別AC出力ログの実績を優先できるようにする。
