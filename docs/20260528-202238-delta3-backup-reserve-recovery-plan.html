DELTA 3 Plus バックアップリザーブ未反映リカバリ実装計画

目的

DELTA 3 Plus 2 の買電時制御で、バックアップリザーブ変更が実機に反映されないまま同じ指示を抑止し続ける状態を解消する。

現状は、買電時に「放電させる」意図で backup reserve 20% を設定しようとしているが、実機の読み取り値は backupReserveEnabled=false / backupReserveSoc=0 のままになっている。そのため、直近コマンドが未反映と判定され、以後の制御候補が抑止されている。

非目的

  • 実機 write の安全ゲートを緩めない。
  • DELTA 3 Plus 1 台目を制御対象に戻さない。
  • AC 出力 ON/OFF の新規 write payload は追加しない。
  • 未検証の private MQTT command を増やさない。
  • .env の既定値を実制御有効側へ変更しない。

現状

  • PlanDelta3AuxCharging は買電時に maybeSetDelta3DischargeReserve を呼び、BackupReserveMinSoc へバックアップリザーブを設定する。
  • executor は ShouldSetBackupReserve を SetEnergyBackupEnabled(true, target) として送信する。
  • 実機ステータスでは backupReserveEnabled=false / backupReserveSoc=0 のままなので、failed/stale 判定になる。

変更方針

買電時の放電リカバリでは、バックアップリザーブを「有効化」しない。

  • バックアップリザーブ有効化は、機種やモードによってパススルー/充電寄りに解釈される可能性がある。
  • 買電を減らす目的では、少なくとも現在の backupReserveEnabled=false は放電を妨げる状態ではない。
  • 反映されない command を繰り返し候補にすると、実際に有効な AC 充電上限調整や今後の制御をブロックする。

実装内容

  1. maybeSetDelta3DischargeReserve を修正し、backupReserveEnabled=false の場合は ShouldSetBackupReserve=false のままにする。
  2. 前回 reserve command が買電リカバリで master min へ下げる目的だった場合に限り、backupReserveEnabled=false / backupReserveSoc=0 を failed ではなく ignored と診断する。
  3. 余剰充電時の reserve 引き上げ失敗は従来通り failed/stale として扱い、再送抑止を維持する。
  4. 買電時にリザーブ操作をしない場合の reason を明確化する。
  5. planner / executor の unit test を追加する。

安全境界

  • 実機 write 条件は既存通り維持する。
  • この修正では新規 write command を追加しない。
  • 既存の最小コマンド間隔、重複抑止、AC 充電上限の安全計算は維持する。
  • 実機 write は追加実行しない。

ロールバック

planner/executor の条件分岐とテスト追加のみなので、問題があれば本差分を戻す。DB migration や実機設定変更は含めない。
