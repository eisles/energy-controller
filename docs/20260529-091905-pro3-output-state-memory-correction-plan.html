DELTA Pro 3 出力状態復帰設定の誤検知修正計画

Goal

outputPowerOffMemory を「AC出力OFF履歴」として扱っている誤判定を修正する。この値は「出力ポートのON/OFF状態を記憶し、電源復帰時に同じ状態へ戻す設定」として扱う。

Non-goals

  • EcoFlow 実機への新しい write 制御は追加しない。
  • 既存DBテーブルの破壊的マイグレーションは行わない。
  • 過去ログは削除・書き換えしない。
  • DELTA 3 Plus 補助充電制御ロジックは対象外。

Current State

  • BuildPro3ACOutputEvent が outputPowerOffMemory=true のみでイベントを生成している。
  • 通知と画面が「AC出力OFF履歴」と表示している。
  • 実ログではこの値が true でも AC出力W と AC周波数が取れており、AC出力は継続している。

Data/API Contract

  • Pro3ACOutputEvent.outputPowerOffMemory は互換のため残す。
  • event_type=ac_output_off_memory は過去互換のため残すが、新規生成条件を変更する。
  • outputPowerOffMemory=true だけではイベントを生成しない。
  • 実AC出力OFFは battery_output_w、acOutFreq、将来の acOutputEnabled で判定する。

Files Likely To Change

  • backend/internal/control/pro3_ac_output_event.go
  • backend/internal/control/pro3_ac_output_event_test.go
  • backend/internal/notify/pro3_ac_output_alert.go
  • backend/cmd/server/main_test.go
  • frontend/components/StatusCards.tsx
  • frontend/lib/types.ts

Implementation Steps

  1. BuildPro3ACOutputEvent の生成条件を修正する。
  2. イベントメッセージを「AC出力OFF相当を検知」に変更する。
  3. 通知文言を同様に修正する。
  4. 画面では outputPowerOffMemory を「出力状態復帰設定」として通常情報扱いにする。
  5. 実OFF相当だけ警告表示する。
  6. テストを更新する。

Safety Boundaries

  • 実機 write は行わない。
  • .env や秘密情報は変更しない。
  • 既存ログの削除やDB改変は行わない。
  • EcoFlow write path には触れない。

Review Points

  • outputPowerOffMemory を警告条件として使っていないこと。
  • 実OFF検知が過剰に発火しないこと。
  • 既存API利用側を壊さないこと。
  • 表示文言が「履歴」と誤解させないこと。

Verification Commands

  • cd backend && rtk go test ./...
  • cd frontend && rtk npm run build
  • rtk curl -s http://localhost:18085/api/status | rtk jq '.pro3AcOutputEvent, .ecoflowDiagnostics.outputPowerOffMemory'

Rollback Notes

問題があれば本修正差分を revert する。DB破壊変更は入れないため、データ移行は不要。
