Tariff Optimized Control Implementation Plan

Goal

料金時間帯を固定時刻ではなく料金マスタから解決し、平日/休日/祝日で異なる単価を考慮して、高単価時間帯は放電優先、低単価時間帯は必要最小限の深夜充電、売電中は余剰吸収を優先する。

Non-Goals

  • 実機write gateを緩めない。
  • EcoFlow/Natureの認証情報やデバイスSNを計画・ログに出さない。
  • 祝日APIのネットワーク依存は追加しない。初期実装は既存の簡易祝日判定を使う。
  • 燃料調整費や再エネ賦課金の完全再現は対象外。

Current State

  • tariff_plans は day_rate_yen、home_rate_yen、night_rate_yen、export_rate_yen を持つ。
  • 料金区分は tariffPeriod で固定判定している。
  • 制御ロジックは主に売電/買電ベースで、料金帯を直接の制御入力として扱っていない。
  • 既存の未コミット差分として、DELTA 3 Max Plus制御と機器ステータスUI調整がある。今回の実装ではこれを戻さない。

Proposed Data Contract

TariffPeriodRule を追加する。主な項目は tariffPlanId、dayType、period、startMinute、endMinute、rateYen、priority。ルール未設定時は既存の3単価から既定ルールを生成する。

TariffControlContext を追加し、現在区分、現在単価、最低/最高単価、高単価/低単価判定、次の低単価切替時刻、日種別を制御へ渡す。

Control Behavior

High Price Period

高単価帯でSOCに余裕がある場合、AC充電上限を最小値へ下げ、バックアップリザーブを制御下限へ下げる。売電中は余剰吸収を優先し、買電中は放電優先にする。

Low Price Period

低単価帯では翌日PV予測と機器ごとの日中必要量を見て、不足分だけ深夜充電する。

Mid Price Period

売電があれば余剰吸収、買電なら無理な充電を抑制する。

Implementation Steps

  1. Add tariff period rule domain structs and SQLite migration.
  2. Extend tariff repository to list/save period rules with backward-compatible defaults.
  3. Replace fixed tariffPeriod usage with rule-based period resolution.
  4. Add TariffControlContext generation for the current status timestamp.
  5. Feed the context into surplus and night-charge planners.
  6. Add high-price recovery behavior.
  7. Add low-price night-charge behavior using existing forecast/device calculations.
  8. Expose active tariff period and optimization reason in status JSON.
  9. Update the tariff settings UI to show/edit weekday and holiday time bands.
  10. Add tests for weekday, holiday, cross-midnight, high-price discharge, and low-price charge.

Safety Boundaries

Real EcoFlow writes remain behind existing gates: ENABLE_REAL_CONTROL=true, SIMULATION_MODE=false, auto-control, confirmation, trial window, and private-write gates. This change alters decision candidates, not the safety gates.

Review Points

  • Migration is backward-compatible.
  • Rule resolution handles weekday/holiday, cross-midnight, overlaps, and missing rules.
  • High-price discharge never drops below reserve lower bounds.
  • Existing surplus absorption still wins during real export.
  • Frontend does not reveal credentials or secrets.

Rollback / Operational Notes

If tariff rule resolution fails, fall back to the old 3-period default mapping. Back up SQLite before production migration.
