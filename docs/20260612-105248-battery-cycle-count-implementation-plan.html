Battery Cycle Count Implementation Plan

Goal

各 EcoFlow 充電機器のサイクル数を読み取り専用ステータスとして取得し、機器ステータス画面に表示する。

  • DELTA Pro 3: EcoFlow Cloud quota に cycles 系の値があれば表示し、Cloud にない場合は同じ SN/type を使う read-only private MQTT 補完でサイクル数だけ取得する。
  • DELTA 3 Plus / DELTA 3 Max Plus / RIVER 2: EcoFlow private MQTT の telemetry から既知または候補のサイクル数を取得する。
  • 取得できない機器は - 表示とし、制御判断には使わない。

Non-Goals

  • EcoFlow への新しい write command は追加しない。
  • サイクル数を使った充放電制御の変更はしない。
  • 未確定の private MQTT field を断定的に寿命診断へ使わない。
  • EcoFlow の認証情報、シリアル番号、トークンをログや計画に残さない。

Current State

TarasKhust/ecoflow-api-mqtt の調査では、サイクル数に関して DELTA Pro 3 の cycles、DELTA 2 系の bms_bmsStatus.cycles、DELTA Pro Ultra の hs_yj751_bms_slave_addr.1.cycles が使われている。

本リポジトリでは、domain.BatteryStatus、ecoflowprivate.Status、Delta3StatusResponse、frontend 型と表示に cycle count field がまだない。

Data/API Contract

{
  "cycleCount": 123,
  "cycleCountSource": "ecoflow_cloud_quota|ecoflow_private_mqtt|ecoflow_private_mqtt_candidate"
}

field は optional。推定値は ecoflow_private_mqtt_candidate とし、画面上も候補であることを示す。

Implementation Steps

  1. Domain/API/frontend 型に cycleCount と cycleCountSource を追加する。
  2. EcoFlow Cloud quota adapter で cycles 系の既知キーを拾う。
  3. EcoFlow private MQTT status に cycle count field と candidate 抽出 helper を追加する。
  4. DELTA Pro 3 の Cloud status に read-only private MQTT cycle 補完を追加する。補完はサイクル数だけに限定し、失敗しても Cloud status を返す。
  5. Cloud/private の API mapping を更新する。
  6. 機器ステータス画面に サイクル数 を追加する。
  7. backend / frontend のテストと build を実行する。

Safety Boundaries

読み取り専用の field 追加のみ。実機 write path、充放電制御、command interval、real-control gate は変更しない。DELTA Pro 3 の private MQTT 補完はサイクル数だけに限定する。

Review Points

  • サイクル数が取れない場合に UI/API が壊れない。
  • 未確定 field を断定表示しない。
  • Cloud API と private MQTT の責務が domain 層へ漏れない。
  • 既存 status API の後方互換性を壊さない。

Verification Commands

Rollback / Operational Notes

追加 field は optional。candidate 判定が不安定なら UI 表示を外し、diagnostics のみに戻す。実機制御の再起動や write command はこの作業範囲外。
